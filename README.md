# 微信美化 · 青屿

为 Windows 微信换上自己的颜色。`#39C5BB` 青屿主题、自定义背景、分区配色、内置使用指南与自研原生绘制引擎。**0.7 预览版新增预览内构图、建议遮罩撤销、版本与教程入口，并精简主题页布局。** 延续 0.6 的微信 4.2 与版本系列适配。

**0.7.1 修复更新**：减少会话列表滚动时重复的类型查找、内存权限查询与磁盘日志写入；通讯录保留微信原生绘制，修复姓名和分组后出现不连续背景块的问题。聊天页继续支持背景与分区配色。

[下载预览版与校验文件](https://github.com/dddedd51/WeChat-Beautify/releases) · [B 站视频教程](https://www.bilibili.com/video/BV1ag4i6xEco) · [来源与参考项目](THIRD-PARTY.md)

> **版本范围：Windows 微信 4.1.15.X 和 4.2.0.X x64（64 位），实测版本为 4.1.15.56、4.2.0.13。** `X` 表示最后一段滚动版本号，例如 4.1.15.57、4.1.15.99。同系列其他构建允许尝试，但未经实测，可能显示异常或崩溃；启动时若关键绘制结构不匹配，会拒绝启用主题。其他 4.2 系列需单独检查，32 位、macOS 和手机微信不支持。

> **使用前请注意：这是非官方、实验性的运行时美化工具，不保证不封号。** 加载第三方模块、改变微信内部绘制可能带来兼容性、崩溃或账号限制风险。请先阅读下方「实现原理」和「账号风险：不保证不封号」；不能接受账号风险时，请勿使用。

## 现在能做什么

- **青屿主题**：青绿色选中项、柔和背景、独立的深浅配色。一键选择后点击「更新主题」。
- **预览内构图**：本地导入 PNG/JPG/BMP，在右侧微信示意图中拖动图片、滚轮或滑杆缩放；虚线标出导航、会话列表、标题、聊天和输入区域。保存后调节模糊与明暗遮罩。
- **分区配色**：导航、会话列表、聊天背景、输入背景、选中会话、列表名称、摘要和选中文字。HEX 输入与颜色选择器可配合使用。
- **可读性检查与撤销**：估算列表名称、摘要及选中项对比度，必要时提供遮罩建议。采用后可撤销一次，恢复之前的遮罩；手动改动遮罩或更换背景后撤销失效。
- **内置教程与更新入口**：左侧「使用指南」包含启动、构图、应用、恢复和常见问题，以及 GitHub 项目、Releases 与 B 站入口。「检查新版本」在浏览器打开 Releases，由用户核对版本，不自动下载执行更新。
- **紧凑主题页**：主题、强调色和微信检测在最小支持窗口下完整显示，无需滚动。背景、配色和指南仍保留必要的滚动能力。
- **恢复默认**：停用本客户端主题，保留微信安装文件和个人图片。
- **按版本系列适配**：自动区分实测构建、同系列试用和待适配系列；不同系列使用独立适配器与运行目录。

## 实现原理

本工具在微信运行过程中调整界面绘制，流程如下：

1. **启动时加载模块**：客户端按微信版本系列选择适配器，通过 Qt 的 `testability` 加载入口载入对应的 `qttestability.dll`。入口检查版本系列与架构，再加载自研 `beautify-engine.dll`；引擎在修改任何绘制槽之前检查目标结构。两个自研 DLL 本身仍须通过完整哈希校验。
2. **接管已适配控件的绘制回调**：引擎修改进程内已核对的共享虚表槽，在文字绘制之前画入背景图片和分区颜色，再由微信原生函数绘制文字。对已支持的列表文字，绘制时临时设置颜色，随后恢复。这样避免了在最终画面上改像素造成的文字白底问题。
3. **本地处理与刷新**：图片裁剪、模糊和明暗遮罩在本机完成；引擎读取更新后的配置并刷新界面。带请求号和进程号的回执用于确认配置应用，不能替代实际画面检查。
4. **停用与退出**：「恢复默认」停用主题绘制；从托盘完全退出微信后，模块和进程内改动随进程消失。下次从原微信入口启动，不加载本工具的主题模块。

**不修改微信安装文件，不等于没有修改微信运行状态。** 本工具会加载第三方 DLL，改变进程内部分绘制函数指向和文字颜色状态。当前实现没有主动读取或导出聊天记录、修改通信协议或自动收发消息的功能，但这些设计限制不代表不会被检测或限制账号。

当前效果是图片模糊与分区半透明叠色，尚未实现实时透出桌面的毛玻璃。更详细的实现与验证边界见 [引擎设计](native/independent/DESIGN.md) 和 [研究记录](native/independent/RESEARCH.md)。

## 使用方法

1. 安装 [.NET 10 Desktop Runtime x64](https://dotnet.microsoft.com/download/dotnet/10.0)。确认微信属于上方适配系列；**仅 4.1.15.56、4.2.0.13 有实机记录，其他同系列小版本为试用**。
2. 将发布 ZIP 完整解压到普通下载目录中的新文件夹，双击 `微信美化.exe`。保留同目录依赖与 `native-runtime` 文件夹；不要只拿走 EXE。
3. 在「主题空间」选择青屿，或到「背景与构图」选择图片。在右侧示意图拖动图片，通过滚轮或滑杆缩放，点击「保存构图」；已有背景可点「在预览中构图」重新调整。取消或切换页面会丢弃构图草稿，保留原方案。
4. 首次启用时，从微信托盘菜单完全退出微信，然后点本客户端的「启动主题微信」，自行完成登录。
5. 进入聊天主窗口后，修改选项并点击「更新主题」。顶部显示连接状态，底部显示本次请求的结果。
6. 需要还原时点击「恢复默认」。从托盘退出微信后，引擎随进程卸载；使用原微信入口启动就是普通微信。

选图、裁剪和颜色只改变本地方案；「更新主题」才应用到微信。普通微信入口不会加载主题。微信已运行时客户端不会强制关闭它。

图片和配置保存在程序旁的 `data`，不会上传。裁剪保留原图副本，取消编辑不覆盖方案。移动整个程序后，旧设置里的绝对图片路径可能需要重新选择。

构图时使用清晰原图，保存后恢复模糊、遮罩与可读性分析。**示意图采用 19:10 比例，仅提供区域位置参考，不读取微信的真实按钮坐标，也不能在微信窗口里直接拖动背景。** 最终裁剪图由引擎铺满真实窗口；窗口比例、尺寸或分栏宽度不同，图片与分区的相对位置也会变化，请以微信里的效果为准。

升级建议：完整解压新 ZIP 到新文件夹，关闭旧客户端后，将旧文件夹的 `data` 复制到新文件夹保留个人方案。原设置引用的图片路径须仍然存在；迁移后找不到图片时重新选择即可。反馈前先在「使用指南 → 检查新版本」核对版本，再导出诊断；诊断可能包含本机路径，请自行检查后分享。

## 构建

Windows x64、.NET 10 SDK、Visual Studio C++ x64 Build Tools、Windows SDK。当前默认构建**不再下载或编译旧上游引擎**，也不需要 Node.js、Ghidra 或 Frida。

```powershell
git clone https://github.com/dddedd51/WeChat-Beautify.git
cd WeChat-Beautify
.\build.ps1
.\test.ps1
```

输出在 `dist/`。完整构建枚举 `native/independent/adapters/*/manifest.json`，为可构建适配器生成独立的入口和绘制 DLL，输出到 `native-runtime/<adapter-id>/`；`pending` 仅用于显示待适配状态，不生成模块。客户端的版本表与模块哈希从这些构建结果生成；不从网络下载并执行适配器。

运行目录同时区分适配器 ID 和两个 DLL 的哈希，防止版本、旧新模块混用。配置通过带唯一请求号的 UTF-16 文件传递；回执匹配协议、请求号和进程。DLL 载入不再单独视为启动成功，须收到 ready/pending/applied 等引擎回执。添加新系列的流程见 [适配器说明](native/independent/adapters/README.md)。

## 实测与限制

**0.7.0 客户端**：沿用 0.6 已实测的两组原生引擎 DLL。增加构图拖动、边界、缩放、重置、建议遮罩撤销与最小窗口布局自检；预览构图不等于对实际微信所有窗口尺寸的逐像素定位。仍依赖 .NET 10 Desktop Runtime x64，未改为内含运行时的大体积发行包。

**0.7.1 引擎修复**：类型表与回调表采用有序查找，每次绘制重新读取父链与几何，避免跨回调缓存控件造成陈旧坐标。九节点离线夹具的内存权限查询由 88 次降至 26 次；类型查找覆盖 2042 项表，查询比较次数不超过 13 次。两个适配器的结构与遍历回归测试通过，覆盖通讯录后代排除、无效指针、循环父链和滚动后坐标更新。用户在 4.2.0.13 的修复版上确认滚动不再明显卡顿、通讯录碎块消失；另已检查恢复默认与重新应用的实际画面及匹配回执。4.1.15.56 本轮仅运行离线回归，未重新实机验证。以上是本机体验反馈，未作跨设备 FPS 基准；服务号等其他页面尚未单独适配，不能据此推断全部页面正确。

**0.6 / 微信 4.2.0.13**：独立解压客户端以普通权限（Medium）启动，实际进入聊天主窗口；观察到自定义背景、原生文字、青绿色选中会话和输入区叠色。点击「恢复默认」后原生背景与选中样式恢复，再点「更新主题」原主题重新生效；两次均收到匹配进程号和请求号的 disabled/applied 回执。用户同时通过「关于微信」页面确认版本。本轮未验证该版本的长列表滚动、其他 DPI、多显示器和长期运行；没有发送测试消息。

以下实机记录来自 **0.5 引擎和微信 4.1.15.56**，不代表其他版本或新系列试用流程已实测：引擎在微信绘制文字之前替换已识别的控件背景，文字继续由原生绘制。已在本机观察到会话行背景、无白底的原生文字、青绿选中项、窗口缩放、滚动、配置更新、停用恢复及同进程引擎重启。客户端与当时运行的测试微信已完成连接和更新回执检查。

便携 ZIP 已在普通下载目录中解压验证：客户端以普通权限（Medium）运行，由用户点击启动按钮，完成登录后显示自定义背景、青绿选中项和原生文字；收到匹配 pid/revision 的 applied 回执。更新图片与停用恢复回执已核对。

开发目录曾继承低完整性标记，导致 EXE 普通双击后仍受限。干净 ZIP 解压到新目录后已解决，无需管理员权限。若出现低完整性提示，请重新解压到普通文件夹；若此前以管理员身份运行过微信，请先从托盘退出，再用普通权限客户端启动。客户端不会自动提权或修改安全设置。

不同 DPI、多显示器、休眠和长期运行未完成覆盖；其他页面逐步适配。编译和离线自检不等于所有实际页面都已验证。因此当前为预览版，尚不作为稳定完整 Release。

可读性结果来自整图 64×64 采样，不读取聊天内容，也不代表实际文字位置或完整无障碍认证。诊断不记录聊天，但含本机路径。

- `src/`：客户端、教程、裁剪、配色、青屿背景生成和对比度检查。
