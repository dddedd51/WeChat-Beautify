# 原生绘制重构调查

## 已确认的原因

当前 DXGI 原型在文字、图片和底色已经合成后修改像素。它不能可靠区分字内部空洞、边框、分割线、灰色图片和背景。实机截图证明连通域修补仍有残留，不能把会话列表局部改善视为全应用修复。

旧引擎在控件背景绘制阶段接管背景，文字通过原有绘制函数栅格化。自研重构采用这个分层原则，不移植旧版的对象记录、遍历、delegate 克隆或像素算法。

## REA 证据

分析对象是本地旧构建 `dist/native-runtime/qttestability.dll`，SHA-256 为 `d5140d5f714ca8f239e692ba4de2057939fbb0d51a5b9a5f0b46b2fcc6af4931`。它包含上游代码和先前的本地扩展，不是纯上游发行包。

- REA 6.5.0 + Ghidra 12.1.4 已完成实际原生反编译。便携 Ghidra 下载自官方发布页并核验官方 SHA-256，只在命令进程中设置运行路径；未修改 Codex MCP 或系统配置。
- 启动入口：`ev_17a8650c35039c75d1764eef475a3c9917074f2f9308b81c038c413b261252e4`，`qt_testability_init`，地址 `0x180005d20`。保存文件：`research/old-engine-entry.json`。
- 文字回调：`ev_9390a4a95c53a4d9fec6f7808bded8f31806662061550fba1f8e1e57bdfa7546`，地址 `0x1800082c0`。保存文件：`research/old-engine-text.json`。末尾转发原始回调，颜色 setter 位于目标模块的 `0x1e9f7e0`。
- Ghidra 的未知间接调用、推断类型和 no-return 警告保留在原始证据中。它们不能当作完整恢复出的 C/C++ 类型。入口中 HMODULE 指针加法有类型缩放，地址核对采用原始指令。

## 对目标微信的独立静态核验

以下来自本地 PE/Capstone 静态检查，不标为 REA 证据。目标为微信 4.1.15.56，SHA-256 `e0428a7b691853de496532523c2c09aa095f90941c37c9f4cfb3f137f3c66556`。

- `0x1ea62d0`、`0x1eb1d40`、`0x40b0c80` 使用 `self - 0xc0` 取得控件；第二参数传递绘制画布。
- 原生背景函数读取控件几何、调用画布保存与恢复，并调用图片及矩形绘制。`0x53fa30` 最终使用画布虚表 `+0x118`；矩形入口 `0x53cd00` 调用虚表 `+0xb8`。
- `0x532fd0` 初始化画笔，`0x533980` 将 ARGB 转为画笔颜色；`0x5332b0` 析构。图片入口 `0x4fd250` 构造 QImage，`0x70b60` 创建拥有引用的包装，`0x4fdbc0` 释放 QImage。
- `0x1e9f7e0` 比较并写入对象 `+0x234`，再通知底层段落对象；这比改最终像素更适合文字颜色。
- PE `.rdata` 的 MSVC Complete Object Locator 确认相关次级接口偏移为 `0xc0`。RTTI 类型名在静态文件中不可读，改用相同类型描述符匹配主接口，再解析其 Qt 元对象字符串，获得 503 个候选对应关系。来源和生成脚本在 `research/`，生成结果为 `paint-targets.generated.h`。表中类型是可用元对象类型，可能是继承的基类类型，不等于每个控件的最具体 C++ 类型。

## 新实现及验证边界

`semantic-engine.cpp` 使用经过启动校验的共享虚表槽，不克隆每个对象。回调按当前对象的父链确认主窗口、区域及受保护内容，只替换识别的背景绘制。文本回调始终转发原始函数。图片缓存由 GUI 线程替换并释放旧引用；停用后继续原生绘制。共享 hook 只在进程结束时卸载，不能宣称运行中卸载 DLL。

实机绘制、配置和恢复的已验证范围见下一节。收藏、发现、网页、消息卡片等未适配内容仍需逐页检查，不能从主界面局部测试推断全应用正确。此前已阅读上游代码，不能宣称法律意义上的 clean-room 实现。

## 原生绘制实测进展（2026-11-06）

REA Frida 会话观测到会话行的父链包含高 17160 的 QWidget 滚动内容、XTableView、ChatSessionList、两层 MainView。原 8192 上限错误拒绝这些行；semantic-layout.h 将滚动几何与根窗口限制分开，并在 MainWindow 之前选最外层 MainView，避免坐标错位。证据 ev_c47d7abd371e074fc3a97a6dfe43ed7f3b552a05b207af71f2ea08efc470426e；原始记录 research/rea-row-trace.json。REA 记录未自动绑定文件哈希，目标进程和已校验安装文件的关联由本次操作核对，不能把该限制省略。

已观察到：列表壁纸出现，原生文字无旧像素方案白底，列表滚动和最大化后背景连续；选中项可设置 #39C5BB 和深色文字；停用后原生背景和原文字恢复。只验证了当前显示器和本机布局，未覆盖其他 DPI/多显示器。

文字 setter 在每帧设置并恢复时触发连续重绘。独立检查 0x1e9f0c0、运行时段落槽 0x44e7bd0 及失效入口 0x6249740，改为缓存失效 notify=false，仍在原生文字 paint 前临时设色并立即恢复。观察日志后连续重绘消失；这不等于跨设备性能基准。

GUI 线程 stop/start 实测通过；不可变 hook 表复用，强制重新读配置，计时器失败回滚，stop 汇总残留 hook。模块始终保留到进程结束，未实现运行时 FreeLibrary。C++ catch 不能捕获普通 Windows 访问异常，不能作为未知 ABI 的保护。

控制器现在使用自研引擎的独立运行目录、双 DLL 哈希及带 revision/pid 的 theme.receipt。动态替换图片和主题更新已观察到。回执表示已读配置并进入原生绘制回调，不证明每个区域的视觉效果。

默认 build.ps1 不再编译或下载上游引擎。区域内共享泛型类型仍需更多页面验证；消息气泡、正文、链接、图标及实时桌面毛玻璃尚未接入，本次客户端不宣称这些能力。当前为预览版。
